# Формировать пары одной камеры при подготовке серии

Локальный ID: FS-03

Общий контракт: [README](README.md)

## Результат

Формировать пары одной камеры при подготовке серии. Выполнить только этот шаг после его зависимостей.

## Файлы для изучения и изменения

- src/data_processing/sort_and_binarize.py

Допустимы небольшие целевые тесты в tests/. Иные изменения — только если непосредственно необходимы этому шагу; объяснить их в итоговом отчёте.

## План реализации

1. Добавить в конец аргументов SortAndBinarize input_mode="actual_flow"; разрешить actual_flow и frame_sequence, неизвестное значение отклонять.
2. Для frame_sequence использовать get_sequence_frames и правила чётности из issue 01. Кадры (1,2), (3,4) сохранять как 1_a.png, 1_b.png, 2_a.png, 2_b.png в cam_1. Суффикс вычислять по позиции, а не копировать из исходного имени.
3. Создавать только cam_1; не отражать изображения серии. Actual Flow сохраняет прежнее чередование и cv2.flip(img, 0).
4. Сохранить структуру binary_filter_<threshold>, существующие результаты, отмену и сообщения прогресса; cam2_count=0 для серии.
5. Не допускать примеси старых пар при повторном запуске серии: если целевой binary_filter_<threshold> уже содержит данные, вернуть понятную ошибку и предложить другую папку результата. Не удалять старые результаты автоматически.

## Критерии приёмки

- [ ] 20 кадров дают ровно 10 пар в cam_1; cam_2 не создаётся.
- [ ] Несимметричный тестовый кадр сохраняет ориентацию; оригиналы не меняются.
- [ ] Нечётное количество отклоняется до записи; повторный запуск в непустой результат не смешивает данные.
- [ ] Режим Actual Flow по умолчанию сохраняет прежнюю раскладку.

## Проверка

Использовать маленькие 16-битные изображения для этой задачи, пока поддержка 8 бит не добавлена; проверить порядок, ориентацию и неизменность оригиналов.

Не требовать доступа к пользовательскому Desktop для автоматической проверки. Не устанавливать новые библиотеки без необходимости; использовать зависимости проекта и временные каталоги.
