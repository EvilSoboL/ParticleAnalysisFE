## Результат

Сканировать папку кадров без AFXML. Выполнить только этот шаг после его зависимостей.

## Файлы для изучения и изменения

- src/data_processing/experiment_preprocess.py

Допустимы небольшие целевые тесты в tests/. Иные изменения — только если непосредственно необходимы этому шагу; объяснить их в итоговом отчёте.

## План реализации

1. Добавить в конец ExperimentRecord поле input_mode: str = "actual_flow", сохранив совместимость существующих конструкторов. Для серии afxml_path="".
2. Добавить scan_frame_sequence(folder: str) -> ExperimentScanResult. Возвращать одну запись input_mode="frame_sequence"; имя брать из родительской папки, если выбран каталог frames, иначе из имени выбранной папки. source_folder указывает непосредственно на кадры.
3. Принимать только PNG с именем frame_<число>.png, сортировать по числовому индексу. Вынести получение упорядоченного списка в get_sequence_frames(folder: Path), чтобы подготовка использовала тот же порядок. Дубликаты числовых индексов и посторонние PNG считать ошибкой, пропуски индексов считать ошибкой: нельзя молча использовать неверный dt.
4. Требовать минимум два кадра и чётное количество. Для серии не применять проверку кратности четырём. Ошибки возвращать через существующий результат сканирования; не создавать файлы.
5. Существующий scan_experiment_root и правила Actual Flow сохранить.

## Критерии приёмки

- [ ] 2, 6 и 20 последовательных кадров дают готовую запись; 0, 1, 3, пропуск и дублированный индекс дают понятную ошибку.
- [ ] Числовой порядок frame_2 перед frame_10 проверен отдельно.
- [ ] Сканирование существующего AFXML по-прежнему находит название и путь.

## Проверка

Небольшие временные каталоги; тест сканирования и регрессия минимального AFXML. Изображения читать здесь не требуется.

Не требовать доступа к пользовательскому Desktop для автоматической проверки. Не устанавливать новые библиотеки без необходимости; использовать зависимости проекта и временные каталоги.
