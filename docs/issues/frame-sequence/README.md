# Issues: последовательность кадров одной камеры

Это заготовки GitHub issues, сохранённые локально; они ещё не опубликованы в GitHub. Номера ниже — локальные идентификаторы, не номера GitHub.

## Цель и границы

Добавить во вкладку автоматического конвейера режим обработки обычной серии без AFXML. Первый релиз: PNG frame_<число>.png, одна камера, пары (1,2), (3,4), 8/16-битные одноканальные изображения, светлые/тёмные частицы, необязательный соседний config.json. Алгоритм PTV и поведение Actual Flow сохраняются.

Не входят: перекрывающиеся пары, JPEG/TIFF/видео, новая система предпросмотра, изменения PIV/Farneback/Kanade, сравнение с droplets.csv, упаковка EXE и публикация GitHub issues. Запуск изменённой программы — из исходников; существующий dist/ParticleAnalysis.exe сам не обновится.

## Как выполнять агентом GPT-6 Luna

- Одна issue — один ограниченный шаг и отдельный коммит/PR при наличии такого поручения.
- Перед выполнением прочитать этот файл, выбранную issue и результаты её зависимостей.
- Следовать зафиксированным контрактам; не проектировать новую архитектуру и не рефакторить соседние подсистемы.
- Новые параметры добавлять с совместимыми значениями по умолчанию. Не менять смысл существующих полей результатов.
- Проверять свою задачу небольшими синтетическими данными. Реальная пользовательская папка не должна требоваться для автоматических тестов.
- Не менять оригиналы кадров, пользовательские настройки, build/, dist/ и посторонние изменения рабочего дерева.
- Завершая задачу, перечислить изменённые файлы, выполненные проверки и ограничения. Если зависимость не готова, сообщить об этом, не реализовывать её целиком попутно.

Это ограничение объёма и явные критерии приёмки для работы по одной задаче, а не обещание фиксированного времени выполнения модели.

## Общий контракт

- input_mode: "actual_flow" (по умолчанию) либо "frame_sequence".
- dark_particles: bool; False по умолчанию в backend. Серия в UI стартует с True, метаданные могут уточнить выбор.
- ExperimentRecord.input_mode — источник режима записи; AutomatedPipelineConfig.input_mode обязан ему соответствовать.
- afxml_path="" допустим для серии.
- Внутреннее имя единственной камеры — cam_1; без отражения и фиктивной cam_2.
- PTVParameters.cameras: ("cam_1", "cam_2") по умолчанию, ("cam_1",) для серии.
- Парообразование: строго неперекрывающееся; нечётное количество и разрывы нумерации отклоняются.
- Порог применяется к исходной яркости. Тёмные частицы: img < threshold; светлые: img >= threshold.
- Метаданные не заменяют проверку реальных изображений. Время хранится в секундах, масштаб в метрах/пиксель.
- Формат результатов сохраняется: binary_filter_<threshold>/cam_1/N_a.png и N_b.png, существующие PTV CSV.
- Все строки пользовательских ошибок нового режима — понятные сообщения на русском.

## Известные особенности исходного кода

experiment_preprocess.py требует experiment*.afxml и кратность четырём. SortAndBinarize извлекает суффикс из имени и отражает cam_1. SortBinarizeParameters повторяет проверку кратности. PTV проверяет обе камеры в анализаторе и исполнителе. full_pipeline.py требует оба итоговых CSV и напрямую обращается к cam_2 при построении гистограмм.

Доступная серия содержит 20 PNG. В её config.json указаны 640×480, 8 бит, 10 мкм/пиксель, 100 мкс; кадры показывают тёмные объекты на светлом фоне. Порог 128 — только ручная стартовая настройка, не подтверждённый оптимум.

## Готовность функции

Задачи 01–10 реализуют функцию; 11 подтверждает сквозную работу и регрессию. Поддержка серии считается готовой после проверки из issue 11, а не после исчезновения ошибки AFXML.
