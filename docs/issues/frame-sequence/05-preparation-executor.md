## Результат

Передать режим серии через исполнитель подготовки. Выполнить только этот шаг после его зависимостей.

## План реализации

1. Добавить в конец SortBinarizeParameters input_mode="actual_flow" и dark_particles=False. Передавать их из set_parameters в SortAndBinarize.
2. В validate разделить правила количества: Actual Flow — кратность четырём, серия — минимум два и чётность с проверкой списка через get_sequence_frames.
3. Не использовать GUI-поля threshold_max как источник фактической разрядности: проверку по содержимому выполняет подготовка из issue 04.
4. Сохранить старые вызовы исполнителя и вспомогательных функций, значения по умолчанию, результат и отмену. Не добавлять параметры в остальные вкладки GUI.

## Критерии приёмки

- [ ] Исполнитель принимает серию из 6 кадров и получает 3 пары без cam_2.
- [ ] Старый вызов без новых аргументов сохраняет режим Actual Flow.
- [ ] Ошибка подготовки возвращается существующим способом, без необработанного исключения.

## Проверка

Один небольшой сквозной тест SortBinarizeExecutor для серии и регрессия проверки кратности четырём.

Не требовать доступа к пользовательскому Desktop для автоматической проверки. Не устанавливать новые библиотеки без необходимости; использовать зависимости проекта и временные каталоги.
